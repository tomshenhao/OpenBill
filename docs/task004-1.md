# Task 004.1: household context and tariff readiness

## What can genuinely be compared

The original 320 observations and source CSV are preserved. A separate reproducible
`regional-monthly-distribution.json` extracts the CSV's published P25, median and P75.
The middle 50% range is regional and includes all household sizes. Below/within/above
that range does not mean wasteful, healthy or normal for a particular household.
There is no interpolated personal percentile. Cell sample counts are unpublished;
the UI displays the published coverage percentage instead. Source dates, geography,
population, licence and limitations remain bound to the original snapshot.

Research reviewed these authoritative sources:

| Source | Finding and decision |
| --- | --- |
| [BRANZ HEEP2](https://www.branz.co.nz/design-build/research-project/household-energy-end-use-project-2-heep2-energy-insights-from-our-homes) | Over 750 households participated in different capacities; collection finished April/May 2025. No suitable public monthly household-size electricity distribution was verified. Participation is not the sample count of a size/month cell. |
| [Stats NZ housing report, Appendix 1](https://www.census.govt.nz/assets/Reports/Housing-in-Aotearoa-New-Zealand-2025/Housing-in-aotearoa-new-zealand-2025.pdf) | HEEP2 recruitment used HES; the sample is almost entirely owner-occupied with older/higher-income bias. It cannot automatically represent all households. |
| [MBIE/Sense Partners report, section 2.2 and appendix](https://www.mbie.govt.nz/dmsdocument/30584-sense-partners-report-lfc-phase-out-pdf) | Published 2023 annual model estimates by household composition AND income exist. They combine HES expenditure-based estimates and EA consumption data. HES typically samples about 3,000 households; rare categories have small samples. These are not measured monthly headcount-only distributions. Do not average income cells, infer composition from headcount, or turn modelled annual means into monthly thresholds. |
| [EA EMI monthly consumption](https://www.emi.ea.govt.nz/Retail/Reports/0YUCE0) | Real regional monthly means and quantiles, without household size. Used only for exact full-calendar-month comparisons. |
| [Stats NZ HES metadata](https://datainfoplus.stats.govt.nz/item/nz.govt.stats/85b6969e-9556-4969-a1ed-8b419f4dfc7e/81) | Expenditure survey information is not a ready-to-use metered monthly kWh distribution by headcount. No expenditure-to-kWh conversion is implemented. |

This is a finding about suitable verified public tables, not a claim that research
data does not exist. A lawful next step, requiring approval before contact, is to
ask BRANZ for licensed, disclosure-controlled aggregate tables by headcount/month,
with sample counts, weights, uncertainty, selection bias and electricity-only
definitions. Researchers can perform approved analysis in their controlled systems;
OpenBill should receive only safe aggregates, never household microdata or linked
identifiers. Suppress small cells and independently review applicability and rights.

No partial-month day-normalisation is offered: dividing by days cannot recover
weather, occupancy or seasonal patterns. The month selector lists only archived
months. Full-month confirmation resets when the month changes; mismatch messages
explain the actual/expected days without asking users to falsify billing days.

The [Authority's procedures](https://www.ea.govt.nz/documents/9748/Requests_for_retailer_product_information_-_Procedures.pdf)
allow any person to request current generally available and still-active legacy
products by phone/email/post. Response is generally within five business days;
alternate delivery/timeframes can be agreed. Standard responses are free; an agreed
alternate format may incur reasonable additional costs. EIE/SFTP requires Authority
approval and an access agreement; one-off requestors can discuss direct delivery or
ask consumer.mobility@ea.govt.nz for procedural advice. Do not register automatically.

Request the current [EIEP14A](https://www.ea.govt.nz/documents/9797/EIEP14A.pdf)
JSON format, product IDs, all distribution networks/regions and price/loss/NSP
restrictions, meters/registers/RCC-POA, schedules/DST, fixed and usage components,
levies/fees, GST basis, discounts and conditions, contract/exit fees, low-user and
other eligibility, and start/end/close dates. Rates in the protocol are GST-exclusive
with discounts separate. Never add a levy or GST twice. There is no verified universal
retailer update frequency: request a written update process and effective-date notice.
The project's 30-day freshness gate remains unchanged.

Access is not a redistribution licence. Obtain written permission for normalized
data, historical versions and screenshots separately, including attribution,
update/withdrawal requirements and restrictions. Do not assume an open-source code
licence licenses supplier data. Three pilot retailers would still be partial market
coverage; no cheapest-in-market claim follows.

## Received-file workflow and limitations

1. Save a permitted, nonpersonal product JSON locally. Keep correspondence containing
   personal sender details outside the source archive; record a nonpersonal receipt reference.
2. Prepare the local request metadata described in `eiep14a-research.md`, using real
   retailer identity, official URL and actual UTC collection time. Run
   `npm run data:eiep14a -- <local-request.json>`. Original bytes and parsed candidates
   are archived by SHA-256 with exclusive creation. The importer accepts a documented
   normative JSON subset, not all EIEP variants; unsupported files require manual handling.
3. Inspect every plan and inherited attribute; resolve network mappings, eligibility,
   dates, units, schedules, GST, all fees and discounts against the original. Never
   infer absent rates, aggregate regions or manufacture missing components.
4. Obtain permitted screenshots and terms/rights references. Mercury retains its
   stricter permission requirement. Existing evidence archive uses approved exact
   official URLs; any new source URL needs review before registration. For Genesis
   and Contact, manual pilot adapters now accept approved-source captures, including
   structurally validated EIEP14A JSON. They do not grant automation or verification.
5. Manually construct pending immutable v0.2 records and bind actual evidence hashes;
   use `data:import`, independent `data:review`, `data:validate`, then
   `comparison:validate`/`comparison:stage` with separate rights receipts.
   The candidate import does not auto-map or verify records. Missing screenshots,
   unresolved scope/conditions and missing rights continue to block publication.
6. Preserve each source/revision and review; recheck on changes and before freshness
   expiry. Stage locally only; public commits and consumer launch require approval.

No official retailer files have been received, so no production tariffs or rankings
were added. The remaining adapter/mapping work is explicitly unverified rather than
claimed complete. Existing engine, synthetic fixtures and verification gates remain.

## 单位与基准说明

目前仍不能按家庭人数比较；地区中间 50% 范围来自真实官方分位数，涵盖所有人数，不是个人排名或健康目标。
只比较同期完整自然月；短账期不能简单按天数放大。新月份选择器只列出真实归档月份。
费率示例：NZ$0.29/kWh = 29 分/kWh；NZ$1.45/天仍填 1.45。异常单位提示不阻止真实特殊费率，
不会自动乘除 100。分时、受控或日夜分类不使用单一费率核对；各项 GST 独立处理，避免重复收费。
零售商申请模板尚未发送。正式电价仍需真实文件、许可、截图、地域与资格核实及独立复核，部分覆盖不代表全市场。
