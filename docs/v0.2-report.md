# OpenBill v0.2 implementation report

Completed locally on `feature/v0.2-electricity-data`. The starting repository was
clean at `090e473`. No commit, push, deployment, account, paid API or cloud service
was introduced. The existing homepage, translations, usage form and browser privacy
behaviour were preserved. The only dependency promotion is Zod 4.6.7, already in
the lockfile transitively and now an explicit schema dependency.

The model represents retail plan, explicit network/region/register scope,
eligibility, contracts, discounts, GST, exact decimal-string daily/usage rates,
flat/time-of-use/tiered/other structures, effective dates and provenance. Full
synthetic example records are in `tests/fixtures/electricity.ts`; none are real
prices, and production import rejects `dataKind: "synthetic"`.

Records and reviews are append-only JSON. Evidence is archived locally under
ignored `.local-data/`, with separate source, screenshot and manifest SHA-256
hashes. Record-bound independent review metadata is necessary for verification;
schema validity alone never verifies a tariff. Missing evidence, corruption,
unsupported assumptions, expiry, supersession and stale captures/reviews block
eligible results. Exact scope matching includes the meter register set.

The Mercury manual-import adapter accepts permitted original official files.
It enforces manual-only collection and explicit Mercury image permission. The
Playwright helper checks permission, conservative robots rules, redirects,
request limits and rate limits; no real retailer is enabled. Its working browser
test uses a synthetic HTTPS source fulfilled locally. Permission-backed evidence
staging remains local/ignored and never commits or uploads supplier material.

## Limitations and unavailable data

No complete, applicable, privacy-compatible numeric retail tariff was obtained
from the six official retailers researched. Therefore no real import, screenshot
publication, independent price verification or savings claim was fabricated.
[The research report](official-source-research.md) contains all official links.
Mercury's terms prohibit scraping and restrict image reproduction; Electric Kiwi
requires an address to view prices; other inspected material did not establish
a complete public rate card. These are observations, not proof that no public
rate card can ever be obtained.

The initial network registry is limited to Vector/Auckland and Orion/Canterbury.
Exclusive/unknown GST, tiered/other calculations, conditional discounts and complex
eligibility are stored but excluded from eligible comparisons. No full comparison
engine exists. Captures and reviews must be less than 30 days old; that maximum is
project policy, not a guarantee that rates remain unchanged. Reviewer/permission
files are human attestations, not signed/authenticated identities. Missing local
evidence on another checkout makes full validation fail closed.

## Run locally and next steps

```sh
npm ci
npm run check
npm run build
npx playwright install chromium
npm run test:e2e
npm run data:validate
npm run data:query -- --retailer mercury
npm run dev
```

Use `npm.cmd`/`npx.cmd` in PowerShell if script execution policy requires it. The
site remains English at `/` and Simplified Chinese at `/zh/`. The
[data guide](electricity-data.md) explains the permission-aware archive/import/
review/staging commands and deliberately invalid templates to fill only with
actual evidence and review findings. No credentials are needed.

For v0.3: obtain permitted complete official rate cards and independent reviewers;
expand supported geography/metering; strengthen identity/repository review and
rights-cleared evidence distribution; independently validate GST, fees, discounts,
holidays, DST and full plan calculations before enabling browser-side comparisons.
